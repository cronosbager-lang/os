# MRM Architecture

## Overview

MixOS Recovery Model (MRM) v2 uses a **Field Resonance Architecture** with Being + Variants.

## Core Components

### Being (Orchestrator)
- Maintains global rhythm and field topology
- Broadcasts to all variants
- Integrates variant contributions
- Decodes final output

### Variants (64 total)
- 8 domains × 8 iteration levels
- Each has unique representation
- Resonate through Kuramoto dynamics
- Cluster through Gravity dynamics

### Field (3D)
- Information propagation medium
- Resolution: 32³ grid
- Diffusion-based spreading

## Dynamics

1. **Kuramoto** - Phase synchronization
2. **Gravity** - Attention/clustering  
3. **Field Propagation** - Information spread

## Learning

1. **Hebbian** - Coupling adjustment
2. **Resonance Tuning** - Frequency adjustment
3. **Attractor Sculpting** - Solution landscape

## Inference Flow

```
Input → Encode → Being Broadcast → Variants Process (parallel)
      → Field Settle → Being Integrate → Decode → Output
```
